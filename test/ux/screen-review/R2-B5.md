Method: one screen at a time. Every frame at 360-light, then 320-light, then 360-light-big (130 % text), then a look at 360-dark, from
test/ux/out/screens/. I did not run the review; the screenshots are taken as current for build 9274da67, as the brief says.
Source read: src/v6/app.js (errors 71-104, Plate 391-437, Builder 440-490, Rescue 492-683), src/v6/legible.css, src/v4/shell.html (base
styles), src/v5/core.js (SAFETY, refer path), src/v5/server.ts (limits), test/ux/review.js (states 121-137, 199-215, failApi 442).

## 065 Plate: could not plan again, last plates kept (plate-error-last)
Purpose: a change of setting asked for new plates, the service failed; the person can retry or go back to the plates made before.

Verdict: findings
1. MINOR. "Show my last plates" does not look tappable. It is italic clay text with no underline and no button shape, under a filled
   Try again; it reads like a caption. The underline was added to links in tips, notes and the menu panel (legible.css:241, 269, 287) but
   not to a link inside an empty card. This is the only way back to the plates that were kept, which is what this screen is for.
   Evidence: 360-light/plate-error-last-1.png; 320-light/plate-error-last-1.png; 360-light-big/plate-error-last-1.png; app.js:406.
   Smallest fix: underline it like the other links (`#app .empty-card .linkbtn{text-decoration:underline;text-underline-offset:3px}`).
2. COSMETIC. The card does not say that the earlier plates are still there, or that the new setting is not used yet. The pill below already
   reads "Quick 15-min" while "Show my last plates" brings back plates made before that change.
   Evidence: 360-light/plate-error-last-2.png (pill), app.js:403-406.
   Smallest fix: add a line under the message: "Your plates from before are kept." 
Dark, 320 and 130 %: the card, the button and the link hold; nothing is cut.

Not inspected: what the person sees after tapping "Show my last plates" (no review frame); a screen reader reading the card.

## 067 Plate: this phone's limit (plate-limit-phone)
Purpose: the daily number of plates is used up; nothing more today; the day line still shows what the meal should hold.

Verdict: findings
1. MINOR. "on this phone" is not what the server counts. The server counts requests per IP address (src/v5/server.ts:100-101, `byIp`).
   On Indian mobile networks many phones share one address, and a family shares the home Wi-Fi. A client who planned one meal can be told
   "You have used today's new plates on this phone", which is untrue for them, and switching from Wi-Fi to mobile data would "undo" it.
   Evidence: 360-light/plate-limit-phone-1.png; app.js:80-81.
   Smallest fix: "Next Plate has had too many requests from your connection today. New plates open again at 5:30 am." (or count per phone
   on the server and keep the words).
Good: no Try again (A13), the next step line is there, the send button is dimmed and the asks give way to one line. Holds at 320, 130 %, dark.

Not inspected: a client outside India (the 5:30 am time follows the phone's clock, app.js:78).

   Evidence: 360-light/plate-not-set-up-1.png (send in full clay; compare the dimmed send in 360-light/plate-limit-phone-1.png); app.js:378, 386.
   Smallest fix: treat not_set_up like the link: `if(/^limit_/.test(j.code)||j.code==="bad_key"||j.code==="not_set_up")UI.lock=j.code;`
   with the ask line "Asks open once your coach switches meal planning on."
Holds at 320, 130 % and dark.

## 071 Plate: asked without the coach's link (plate-ask-no-code)
Purpose: an ask was refused because the code is not accepted; the earlier plates stay; asks are locked.

Verdict: findings
1. MINOR. The words do not fit this case. Every phone in this state already holds a code (review seed `k: CODE`); the server refused it,
   most likely because the coach's code changed. The note still says "Open the link your coach sent you on WhatsApp once. After that, this
   phone remembers it." The phone did remember it, and opening the same old link again will fail the same way. The client is not told to
   ask for a new link.
   Evidence: 360-light/plate-ask-no-code-1.png; app.js:72 (ERRS.bad_key, written for a first visit with no code), 100, 412.
   Smallest fix: when KEYCODE is set, say "The link saved on this phone no longer works. Ask your coach for the link again on WhatsApp and
   open it." and keep the first-visit wording for a phone with no code.
Good: no Try again (A13), send dimmed, asks give way to one line, plates stay. Holds at 320, 130 % and dark.

Not inspected: whether opening a new link (?k=) replaces the refused code without a reload problem.
