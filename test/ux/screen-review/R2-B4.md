## 053 Sheet: my food closed above the sheet (sheet-food-closed-by-band)
Purpose: after a change in My food, closing the sheet any way other than Done still makes the plates again.
Earlier findings: the B3 17-1 BLOCKER is fixed. closeSheet() compares the answers with those from when the sheet opened, and clears and saves the
plates on any way out (app.js:690-693). The captured plate shows "No nuts" on a newly made plate (360-light/sheet-food-closed-by-band-1.png).
Focus returns to the My food line, with a visible ring.
Verdict:
1. MINOR: any change in My food throws away every plate of the day before the new ones arrive. On closing, `STORE.res={};STORE.shown={}`
   (app.js:693) empties all meals. If the new request then meets the daily limit or fails, the person has no plate for any meal, and
   "Show my last plates" has nothing to show (lastForMeal, app.js:65). Clients near the limit who change a goal, or only their activity, lose
   every plate with no warning. Dropping the old plates is right for a leave-out or a health change, but not for every answer. B3 17-2 asked
   for "never delete the last plates before the new ones arrive"; FIXES row 91 fixed only the no-change case. Fix: keep the old plates out of
   view but in STORE until the new plate arrives, or drop them only when diet, leave-outs or health changed.
2. COSMETIC: the screen book says "tap above the sheet" (atlas/names.js:90), but the review closes with Escape (review.js:245). A phone has no
   Escape key, so the tap on the band (app.js:749) is never driven. Both paths call the same closeSheet(), so the behaviour is the same today.
   Fix: click the scrim at a point above the card in the review state.
Not inspected: the Android back gesture with the sheet open (no history handling); the sheet itself in this state (the frames show the plate afterwards).

## 055 Sheet: I had something else, working (sheet-log-wait) (new since the first pass)
Purpose: show that the typed meal is being worked out.
Verdict:
1. MINOR: there is no time line. Every other wait in the app says "It can take a minute or so." (waitCard, app.js:292; FIXES B1 05 row 2, "under
   every wait line"). This wait shows only "Working out what that adds up to" (app.js:719). The request can run up to 95 s (app.js:86), and a
   client who sees nothing change for 30 s will close the sheet. Evidence: 360-light/sheet-log-wait-1.png. Fix: add the same tsub line under it.

   spent, with no word. Fix: when the sheet is reopened while a result or a wait is pending, keep them; or say "Still working, keep this open."
   next to Close.
3. COSMETIC: the three dots can wrap alone. This line does not use waitLine() (app.js:289), so the no-wrap fix of B4 33-3 does not reach it. The
   base dots animation still runs: animations override the `content:none` at legible.css:288. At 130 % "to" ends the line
   (360-light-big/sheet-log-wait-1.png). Fix: build the line with waitLine().
Good: Count it is visibly off; the typed meal stays.
Not inspected: the animated dots in motion (stills only).

## 063 Plate: opened without the coach's link (plate-no-code)
Purpose: tell the person the app needs the coach's WhatsApp link.
Earlier findings: the asks give way to "Asks open once your coach's link is opened on this phone." and send is off (360-light/plate-no-code-2.png).
A phone with no code now sees this card before set-up (owner decision, setup-no-code). The wording is the owner's decision.
Verdict:
1. MINOR (owner question): the rendered case is a kept code that the server refuses, and for that case the message asks for what was already done.
   The review seeds a code (seed() includes k, review.js:37) and the server answers bad_key. The server refuses any key other than the one code
   (src/v5/server.ts:86). On a set-up phone the only ways here are a changed code or an old phone with no code. A person whose old link carries
   the old code is told "Open the link your coach sent you on WhatsApp once. After that, this phone remembers it." Opening it gives the same
   refusal. Fix (for the owner to decide, since the wording is his): for a refused code that is kept on the phone, add "If you already did,
   ask your coach for a new link."
2. COSMETIC: the screen book route "Type nextplate.in without the link" (atlas/names.js:33) no longer reaches this screen. A phone without a code
   meets setup-no-code first (app.js:150). Fix: "A set-up phone whose kept code is no longer accepted."
Also 060-1. Builder and Rescue failing on use is part of the decided row B3 28-1/28-2 and is not repeated.
