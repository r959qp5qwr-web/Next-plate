## 021 Plate: meal skipped while on medicines (plate-skipped-meds)
Purpose: records a skipped lunch and warns a client on insulin or sugar tablets that skipping can drop their sugar.

Verdict: findings.
1. BLOCKER. Right under the low-sugar warning, the card says "Little is left for a snack today." and offers "Plan dinner" as the main
   button. That is untrue here, and it steers someone on insulin or sugar tablets who has just skipped lunch away from eating until dinner.
   - Evidence: 360-light/plate-skipped-meds-1.png and -2.png. The Today line says "About 1700 kcal ... So far 350 kcal ... Dinner: about
     610 kcal". So 1350 kcal are left, not "little".
   - Cause: nextOffer() (src/v6/app.js:135-136) tests the snack's capped target, not what is left. The usual snack is 5 % of the day
     (params.js:34) and catch-up is capped at 1.25 times that (params.js:37). The snack target therefore stays under 120 kcal on any day
     under about 1900 kcal, which is almost every weight-loss or diabetes day. The owner's decision reads "under 120 kcal left for the
     snack" (UX-CRITERIA part A). The code shows the line whenever the snack is small by design, so this screen contradicts the decision's
     premise.
   - Why it matters: the warning above says a skipped meal can drop their sugar. The next line tells them there is little room to eat, and
     the main button skips the snack. For this client that is unsafe guidance.
   - Smallest fix: never show the low-snack line or skip the snack after a skipped meal on medicines (onMeds()). Offer "Plan snack" as the
     main button there. In general, base the line on what is left (PL.left.kcal), not on the snack's capped target. The wording and the
     threshold for the general case are for the owner to confirm.
   - Criteria: B6, owner rule 3 spirit (safety), owner decision 13-2.
2. COSMETIC. The meal tab still draws "Lunch –" (a dash). It is spoken "Lunch, skipped", but on screen the dash is a cryptic mark
   (360-light/plate-skipped-meds-1.png; app.js:284).
   - Fix: a small "skipped" word, or the x icon used by "Skipped it".

Not inspected: whether the coach wants a snack prompted after a skipped meal on insulin (a clinical choice for the owner); live text.

## 024 Plate: no one-tap changes for this plate (plate-tune-failed)
Purpose: when the one-tap changes could not be made, the dead buttons are removed and one line says so.

Verdict: findings.
1. MINOR. "No one-tap changes for this plate." is not what happened. The state is a failed request (review.js:193 returns 502
   upstream_error), not a plate with no changes.
   - Swaps vanish too, silently: no Swap link (360-light-big/plate-tune-failed-3.png).
   - There is no way to try again. The failure is kept only in memory (app.js:112; save() is not called), so a reload would try again,
     which shows "for this plate" is not true.
   - Why it matters: the client concludes this plate cannot be made gentler on sugar, when the service only failed once.
   - Fix: on a failed request say "One-tap changes and swaps didn't load." with a small "Try again" that clears tuneFailed and calls tune().
     Keep "No one-tap changes for this plate." for a reply that offers none.
   - Criteria: B6, A13 spirit (Try again where trying again can help).

Not inspected: a reply that offers some changes but not all (the "Not offered for this plate: ..." line).

     tikka"), or show the swapped item names as the title. Log that title. Hide taste notes and pair lines that name the swapped food, or
     mark them "for the original plate".
   - Criteria: B1, B11, owner rule 5 spirit (the record must match what was eaten).
