# Safety invariants

These are the owner's rules written as properties a test can check. Each holds on every path a client can reach:
- plates (meals, ask, tune: swaps and one-tap changes);
- menu orders: removed from the app (owner, 17 Nov; see "Menu reading removed" under Tiers). The menu code is dormant and unreachable;
- Rescue (dish and moves);
- "I had something else" (log), for S7, and for S8 in what the engine writes there (the figures; the model's "assumed" line is not shown). The log is what the client says they ate, their own record and not an offer, so it is not filtered by the food rules (S1-S5, S9). What it shows back is in the client's own words.

`test/safety/check.js` tests them on the built engine (np-core); `test/safety/codex.js` holds the Codex re-audit's probes with their assertions inverted (a defect fails); `test/rules/check.js` and the review states in `test/ux/review.js` hold the rest. Cases come from `test/safety/lexicon.json`, kept apart from the engine's own word lists: "known" names may be copied into the word lists, "heldout" names never are (the test asserts none appears in `src/v5/core.js` or `src/v6/engine.js`). `test/safety/audit-names.json` (the second audit's 380 names) and `test/safety/controls.json` (573 names the live model wrote) are kept as test data.

**The recorded replies are tested, not only diffed (fix-r12).** Three audits in a row found a new gap in names the live model wrote, in records the checks only compared between builds. `test/safety/recorded.js` (in `npm run safety`, on the three pages) runs two checks over every recorded plate under `eval/`:
- S1-S4 replay, tags stripped: every plate in `reply.meals` and `reply.raw.meals` (items, swaps, one-tap changes, the grain), with every contains tag set to "plain", through the plate check for ten profiles (vegan, dairy left out, Jain, vegetarian, egg-eater, wheat, nuts and soya left out, high BP, diabetes). An offered name (item, swap, added item, the grain's food) that holds a word of the barred class from the lexicon's "known" lists fails; a word negated alone ("without ghee") is S1's own reading. Honest names are allowed whole, each with its reason (the millet rotis, "Thin coconut milk"). With diabetes, a plate shown at a main meal keeps its grain (S5). On 1c58b89: 4 failures ("Brown rice curd rice", vegan and dairy left out); on fix-r12: 0, with 15,458 plates shown (at least 598 per profile).
- S8 scan: every recorded name (plate items, titles, subtitles, swaps, one-tap items, the grain's food, the old records' plate names and item strings) through `showName`, and every name and engine sentence the plate path shows. On 1c58b89: 5 failures and no shared measure list; on fix-r12: 0.

## Tiers (owner, 16 Nov, option survey: "Two tiers (Recommended)")

**Tier 1 blocks release.** Each has a deterministic check and a test that fails on a regression:
- food rules held by declared tags and the word lists (S1-S4, S9);
- the grain stays (S5);
- the medicines floor (S6);
- referral, ticked or typed, plus the urgent-symptom first net (S7);
- figures agree (S13);
- grams and kcal only (S8);
- app logic: S10-S12, the kept-plate rule stamp, Builder bounds (S14).

**Tier 2 is a watched backlog**, with a frequency note and the weekly live sample. It blocks only if seen in ordinary use. It covers counter-examples that need a scripted model reply built to break a filter, with no live occurrence:
- odd or look-alike characters;
- negation parsing;
- sentence meaning;
- a wrong but non-empty tag on a name the lists do not know (tracked: 175 of the second audit's 380 names pass with a wrong tag; `test/safety/codex.js` prints Kori rotti, Payesh and Poondu rasam as TRACKED);
- counts written in words the app does not know, with no occurrence in the recorded live replies ("Rendu idli", "Don chapati", "Duto ruti"): on the watch list, checked in the weekly 20-reply sample; they block only once one is seen in ordinary use. English and Hindi number words, digits and brackets stay tier 1 (owner, 16 Nov, option survey: "Watch list (Recommended)").

How S1-S4 and S9 are held (owner, 15 Nov, option survey: "Declared contents (Recommended)"):
- The model tags every plate item, swap, one-tap change, menu order and side, "leave for another day" entry and Rescue dish from a fixed list: meat, fish, egg, dairy, wheat, nuts, soya, onion_garlic, root_veg, sweet, salty_side, grain, supplement, plain. - **The raw-field rule (fix-r14; safety audit of 7eaadcf, B1, M1, M2 and m3, one cause: the engine cut, blanked or joined a model field before the check read it).** Every safety check reads the whole field the model wrote, folded at intake and nothing else (`modelText` in `src/v5/core.js`); cleaning, cutting and blanking are only for what is shown or travels with an element. Two fields the model wrote are read apart, never joined into one text (the Rescue dish name and the client's typed text; a plate's names are read with a stop mark between them). **Drop over the cap:** an array or a text over its cap, a text in a script the checks cannot read, or a field that is not text drops the element it belongs to; it is never cut to fit. The caps: plates in a reply 4 (the reply is not read), items on a plate 7 (the plate), a plate title 70, an item, grain or swap name 200, what a grain or base swap is made of 40 (the plate or the swap), swaps in a list 3 (that list), a one-tap item 200 (the change), taste words 3 and each word 20 (no taste notes), hooks cited 4 (none named), the Rescue dish name 80 (the dish is not helped), log items 8 (the reply) and each log item name 60 (the item). The meals and tune schemas do not carry the array caps (fix-r17: `maxItems` on them made the live model answer 400 "too many states for serving" on 18 Nov); the engine holds every cap above and drops what is over it, which is what closed audit M2 (an eighth item). Only the log schema carries one (`maxItems` 8), which the live model accepted on 18 Nov. The subtitle, never shown, is read whole up to 1,000 characters and drops the plate beyond: a cap for time only (fix-r15; safety audit of c666d34, m9: a 60,000-character subtitle took about 1.4 s a plate), about five times the longest of the 1,157 distinct recorded subtitles (209 characters; 20 run past 120). `test/safety/inject.js` (in `npm run safety`, on the three pages) is generated from each live kind's schema and writes into every leaf the model may write (see S1 below).
- **The figure rule (fix-r15; safety audit of c666d34, B1 and m5: the numeric half of the raw-field rule).** A figure the model writes on a live path (a plate, an item, the grain, a swap, a one-tap change, the Rescue dish, the log) is read as written (`fig()` in `src/v5/core.js`) or its element is dropped: an integer inside the field's range is the figure; past either end of the range, a zero where zero is no amount (an item's or a swap's grams, a plate's or a dish's kcal, the grams of a food a change adds), null, an empty string, a number written as a string, a fraction, a word or true drops the plate, the swap, the change, the Rescue dish or the log reply. Nothing is cut or rounded to fit, so **a figure shown or checked is the figure the model wrote, or the element is dropped**. The ranges (the engine's, unchanged): a plate 40-2,500 kcal, protein 0-250 g, carbs 0-400 g, fats 0-200 g, fibre 0-80 g, minutes 0-180; an item and a swap 1-800 g; the grain 0-1,500 g; a swap's deltas kcal -400 to 400, protein -40 to 40, carbs -80 to 80, fats -40 to 40, fibre -20 to 20; a change's deltas kcal -400 to 400, protein -10 to 40, carbs -80 to 40, fats -30 to 30, fibre -10 to 20, minutes 0-180, grain grams after 0-800, a food added 1-500 g; the Rescue dish and the log 40-4,000 kcal, protein 0-300 g, carbs 0-500 g, fats 0-300 g, fibre 0-80 g, a log item 1-1,500 g. A field an older reply shape leaves out (a change's minutes and grain grams after, the grams of a change that adds no food, a plate's minutes, the grain's grams) is read as not given; a figure the checks need that is left out drops its element, as before. A swap, a change or a combination of them that takes the plate out of a plate's ranges is not offered, and the app floors no figure (a composed figure under 0 is refused; the Rescue figures shown and logged are the checked ones). The log shows the kcal written: a reply whose kcal is more than a fifth off its macros is not read ("didn't read as a meal"; it used to put its own figure in place, a decision this rule reverses; 0 of the 30 recorded log replies were). `num()` reads only the phone's own fields (the profile, the context, the food file). - **The schema rule (fix-r17; the 18 Nov deploy attempt of 50090ef).** The response schema the model is asked to answer in is part of intake, and no gate sees whether the live model accepts one: 50090ef passed both gates, and every meals request failed (502, Gemini 400 "constraint that has too many states for serving") because of item limits added to the schema, after four reports had said "maxItems configured, not live-validated". (2) A schema change needs a deliberate `--update` of the snapshot; a new schema is `pending`. (3) It becomes `accepted_by {commit, date, how}` only after a live sample window has shown the model answering in those bytes (`--accept`), recorded by the builder from that window's results; external opinion and a passing gate are not acceptance. (4) `test/deploy/schemas-accepted.js` fails while any schema the served page sends is pending; it counts every pending entry (those only a request without the app's `lite` flag builds included) and is run before every "Deploy." ask and is not part of `npm run safety`, since it can only pass after a window the owner has approved. A change that adds a limit, a field, an enum value or a hook name to a response schema is a schema change. The limit of the check: it covers the enumerated schemas (the recorded bodies and the grid), not the whole space; the meals schema is built from the day's hooks in order, and a `repeat_` hook carries a word from the client's own log, so another schema can exist that no entry names. Acceptance is a commit, a date, how and an answered line in a committed window record (`test/safety/schemas/window-<commit>-<date>/schemas.log`) and nothing else: the list of acceptances recorded elsewhere was retired, and the entries it held (the 17 Nov referral window's meals schema, the 18 Nov live check's log and Rescue schemas) are pending until a window re-sends them.
