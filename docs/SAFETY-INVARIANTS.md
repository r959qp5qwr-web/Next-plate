# Safety invariants

These are the owner's rules written as properties a test can check. Each holds on every path a client can reach:
- plates (meals, ask, tune: swaps and one-tap changes);
- menu orders: removed from the app (owner, 17 Nov; see "Menu reading removed" under Tiers). The menu code is dormant and unreachable;
- Rescue (dish and moves);
- "I had something else" (log), for S7, and for S8 in what the engine writes there (the figures; the model's "assumed" line is not shown). The log is what the client says they ate, their own record and not an offer, so it is not filtered by the food rules (S1-S5, S9). What it shows back is in the client's own words.

`test/safety/check.js` tests them on the built engine (np-core); `test/safety/codex.js` holds the Codex re-audit's probes with their assertions inverted (a defect fails); `test/rules/check.js` and the review states in `test/ux/review.js` hold the rest. Cases come from `test/safety/lexicon.json`, kept apart from the engine's own word lists: "known" names may be copied into the word lists, "heldout" names never are (the test asserts none appears in `src/v5/core.js` or `src/v6/engine.js`). `test/safety/audit-names.json` (the second audit's 380 names) and `test/safety/controls.json` (573 names the live model wrote) are kept as test data.

**The recorded replies are tested, not only diffed (fix-r12).** Three audits in a row found a new gap in names the live model wrote, in records the checks only compared between builds. `test/safety/recorded.js` (in `npm run safety`, on the three pages) runs two checks over every recorded plate under `eval/`:
- S1-S4 replay, tags stripped: every plate in `reply.meals` and `reply.raw.meals` (items, swaps, one-tap changes, the grain), with every contains tag set to "plain", through the plate check for ten profiles (vegan, dairy left out, Jain, vegetarian, egg-eater, wheat, nuts and soya left out, high BP, diabetes). An offered name (item, swap, added item, the grain's food) that holds a word of the barred class from the lexicon's "known" lists fails; a word negated alone ("without ghee") is S1's own reading. Honest names are allowed whole, each with its reason (the millet rotis, "Thin coconut milk"). With diabetes, a plate shown at a main meal keeps its grain (S5). On 1c58b89: 4 failures ("Brown rice curd rice", vegan and dairy left out); on fix-r12: 0, with 15,458 plates shown (at least 598 per profile).
- S8 scan: every recorded name (plate items, titles, subtitles, swaps, one-tap items, the grain's food, the old records' plate names and item strings) through `showName`, and every name and engine sentence the plate path shows. On 1c58b89: 5 failures and no shared measure list; on fix-r12: 0.

## Tiers (owner, 16 Nov, option survey: "Two tiers (Recommended)")

**Tier 1 blocks release.** Each has a deterministic check and a test that fails on a regression:
- food rules held by declared tags and the word lists (S1-S4, S9);
- the grain stays (S5);
- the medicines floor (S6);
- referral, ticked or typed, plus the urgent-symptom first net (S7);
- figures agree (S13);
- grams and kcal only (S8);
- app logic: S10-S12, the kept-plate rule stamp, Builder bounds (S14).

**Tier 2 is a watched backlog**, with a frequency note and the weekly live sample. It blocks only if seen in ordinary use. It covers counter-examples that need a scripted model reply built to break a filter, with no live occurrence:
- odd or look-alike characters;
- negation parsing;
- sentence meaning;
- a wrong but non-empty tag on a name the lists do not know (tracked: 175 of the second audit's 380 names pass with a wrong tag; `test/safety/codex.js` prints Kori rotti, Payesh and Poondu rasam as TRACKED);
- counts written in words the app does not know, with no occurrence in the recorded live replies ("Rendu idli", "Don chapati", "Duto ruti"): on the watch list, checked in the weekly 20-reply sample; they block only once one is seen in ordinary use. English and Hindi number words, digits and brackets stay tier 1 (owner, 16 Nov, option survey: "Watch list (Recommended)").

**List gaps (owner, 16 Nov, option survey: "Fix found, then watch (Recommended)").** Every gap an audit or review finds is fixed and tested. How S1-S4 and S9 are held (owner, 15 Nov, option survey: "Declared contents (Recommended)"):
- The model tags every plate item, swap, one-tap change, menu order and side, "leave for another day" entry and Rescue dish from a fixed list: meat, fish, egg, dairy, wheat, nuts, soya, onion_garlic, root_veg, sweet, salty_side, grain, supplement, plain. A food with none of the others declares "plain". Code drops anything whose tags break the client's rules. A missing list, an empty list (the owner's literal rule) or an unknown tag is dropped.
- The word lists are the second net, read on the raw name (brackets and comma tails included: "Veg thali (papad, pickle)" is dropped for high BP). Both checks must pass.
- **The raw-field rule (fix-r14; safety audit of 7eaadcf, B1, M1, M2 and m3, one cause: the engine cut, blanked or joined a model field before the check read it).** Every safety check reads the whole field the model wrote, folded at intake and nothing else (`modelText` in `src/v5/core.js`); cleaning, cutting and blanking are only for what is shown or travels with an element. Two fields the model wrote are read apart, never joined into one text (the Rescue dish name and the client's typed text; a plate's names are read with a stop mark between them). **Drop over the cap:** an array or a text over its cap, a text in a script the checks cannot read, or a field that is not text drops the element it belongs to; it is never cut to fit. The caps: plates in a reply 4 (the reply is not read), items on a plate 7 (the plate), a plate title 70, an item, grain or swap name 200, what a grain or base swap is made of 40 (the plate or the swap), swaps in a list 3 (that list), a one-tap item 200 (the change), taste words 3 and each word 20 (no taste notes), hooks cited 4 (none named), the Rescue dish name 80 (the dish is not helped), log items 8 (the reply) and each log item name 60 (the item). The schema carries the array caps as `maxItems` (configured; not yet checked against the live model). The subtitle has no cap: 20 recorded subtitles run past the old 120, and none is shown (owner question); it is read whole. `test/safety/inject.js` (in `npm run safety`, on the three pages) is generated from each live kind's schema and writes into every leaf the model may write (see S1 below).
- Text is normalised once at intake (NFKC; format characters and combining marks on Latin letters removed; typographic apostrophes and dashes become the ASCII ones, before and after NFKC, so "I can’t breathe" reads as "I can't breathe" (safety audit of b4633dd, B1)). Text in a script the checks cannot read is not shown (the menu's note for a menu in another script is dormant since 17 Nov).
- The app's example asks and Rescue dish taps carry hand-written tags (`APPASKS`, `APPDISHES` in np-core) and are filtered by tags and word lists.

**Where every shown string comes from.** No model-written sentence is shown (safety round 5); the reason line is the engine's (usefulness brief). Four origins:
1. Engine-written from checked structured fields (names, grams, kcal, enums).
2. A model name: checked by tags and word lists on the raw name, then shown cleaned (bracket groups, a comma tail, counts (in digits or words) with their measure word and a menu price taken off; it must then be ASCII letters, spaces and hyphens, with no katori). A name that cannot be cleaned to that shape is dropped.
3. The client's own typed words, shown as typed (a typographic apostrophe or dash in its ASCII form).
4. App-static text, food-neutral except hand-tagged, profile-filtered lists.
