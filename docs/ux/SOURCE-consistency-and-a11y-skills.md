### 0.2 How to read the tables

- **Threshold** is the number as the source writes it, quoted or closely paraphrased, with the
  WCAG level where the source gives one. "No threshold in source" means the skill gives no
  number. Where two sources give different numbers, both are written and the row is listed in 1.6.
- **Check**: **A** = automatic (computed style via `getComputedStyle`, bounding boxes via
  `getBoundingClientRect`, WCAG contrast arithmetic, axe-core rule IDs, CSS/DOM grep, Lighthouse);
  **V** = visual (screenshot or live interaction, keyboard or screen reader). The axe rule IDs
  and DOM probes are the reviewer's way of running the source criterion; they are not quoted
  from the skills unless the source names them.
- **Which standard.** UC `accessibility/SKILL.md`: apply no standard by default; when somebody
  asks for accessibility and the project states no rule, use an external standard "named as the
  one used, never as the project's rule", and the one it names is **WCAG 2.2 AA**. A project rule
  (theme setting, linter rule, written rule) overrides it. This document was asked for, so WCAG
  2.2 AA is the standard used here; AAA rows are listed because the sources list them.
- **Viewport widths in sources**: 320 px (WCAG 1.4.10 reflow, DSK), ~360 px minimum
  (DSP `shared/data/design-principles.csv`, "Design Across Viewport Scales"), 375 px and 1024 px
  (DSP `shared/knowledge/layout.md`).

## 2. Verification procedures the skills prescribe

### 2.1 ui-consistency (UC `verifying`, `calibration.md`, `implementing`, `accessibility`)

- **Never the author.** A separate agent checks; "A fresh turn in the same session is the same
  agent". If none is available, say plainly the author checked its own work. One checker per
  work and kind of page, kept for every page of that kind and the final whole-set comparison.
  (`verifying/SKILL.md`)
- **Prove it can see first.** The dispatcher (never the checker) gives the checker a copy of the
  reference with one planted difference, telling it only that the copy differs somewhere. A plant
  counts only when reported as a difference of the page. If missed, "the check is blind for that
  kind of difference" and nothing is passed. Report what the plant tested and what no plant
  tested. Once per work and kind; a small change owes one plant at the changed position. The
  calibrated agent is not the one that then checks pages. (`verifying/calibration.md`)
- **Read the checklist and the page first** (8-12 lines; each line carries the piece, how it is
  written and what settled it); re-derive from code any region the checklist does not carry,
  with the search proven on the reference first. (`verifying/SKILL.md`,
  `finding-patterns/checklist.md`, `conventions/SKILL.md`)
- **Compare region by region** in reading order: holders, component per role, duplicate roles,
  element and heading level, reused pieces, what the user sees happen, regions moved between
  holders, words, values through the theme, theme entries that exist, spacing on the base, type
  bundles, contrast pairs in every scheme, then focus / reach / labels / text alternatives /
  target size / structure, each reported separately. Report only what differs; "True, but not
  this task's" goes under its own heading. (`verifying/SKILL.md`)
- **Rendered vs code.** "Unless the page was rendered, name what only rendering shows as
  unevaluated: the size a region turns out at, overflow, which minimum or maximum wins, what
  scrolls, overlapping hit areas, gestures." Find every stylesheet the page loads before
  claiming nothing is unevaluated; "No differences never means the page is right". End with
  cost: pages compared, files opened, searches run. (`verifying/SKILL.md`)
- **Whole set at the end.** After the last page of a kind, compare all pages of that kind
  together. (`verifying/SKILL.md`)
- **Fix loop.** Fix and re-check "twice at most"; list what is still open in the checker's
  words; a report that keeps changing is a checklist or checker problem.
  (`implementing/SKILL.md` step 15)
- **Accessibility order.** Family first; project rule if stated; else WCAG 2.2 AA named as the
  standard used; name what could not be evaluated per subject; end with one sentence saying the
  standard's other criteria were not checked, "so the report never reads as conformance".
  (`accessibility/SKILL.md`)

### 2.2 design-skills accessibility-audit (DSK)

- **Five layers, in order:** (1) automated scan, 10 min (axe DevTools, WAVE, Lighthouse, Pa11y;
  one scan finds ~30-40%, a full automated stack ~70-85%); (2) keyboard-only, 15 min (8-item
  checklist incl. focus hidden by sticky content); (3) screen reader, 20 min (VoiceOver or NVDA:
  images, labels, buttons, headings, landmarks, status messages, decorative hidden, custom roles);
  (4) visual and content, 15 min (contrast, 200% resize, 320 px reflow, text spacing, targets,
  hover content, drag alternatives); (5) flows, 15 min (errors, required fields, redundant entry,
  authentication, consistent help, skip links, time limits, media, reduced motion). (`SKILL.md`)
- **Budgets:** quick audit 30 min; full audit "2-3 Hours Per Page" with the minute plan in
  `references/testing-tools-and-techniques.md`. Keyboard script of 12 steps; "What to Listen
  For" table for screen readers; grayscale and vision-deficiency emulation; zoom 200% and 400%;
  text-spacing bookmarklet; reduced-motion emulation.
- **Severity:** Critical / High / Moderate / Low; WCAG level as priority signal; Tier 1 (fix
  before next release) to Tier 3 (backlog). Report template carries "What Passed" and per-page
  keyboard and screen-reader result tables. (`templates/audit-report-template.md`)
- **CI gating:** eslint `--max-warnings 0`, jest-axe, Playwright + axe with tags `wcag2a`,
  `wcag2aa`, `wcag22aa`; "Test components in each interactive state"; manual keyboard and
  screen-reader pass remains required. (`references/testing-tools-and-techniques.md`)

### 2.3 design accessibility-review and design-critique (DSG)

- Testing approach: automated scan (~30%), keyboard-only, screen reader, contrast verification,
  zoom to 200%. Output tables per POUR principle, a colour contrast table (foreground,
  background, ratio, required, pass), keyboard table (Tab order, Enter/Space, Escape, arrows),
  screen-reader table. (`accessibility-review/SKILL.md`)
- Critique framework: first impression (2 s), usability, hierarchy, consistency, accessibility;
  include "What Works Well" and three priority recommendations; match feedback to stage.
  (`design-critique/SKILL.md`)

### 2.4 design-superpowers design-review (DSP)

- Detect maturity level (L0 none, L1 `DESIGN.md`, L2 `.ds-context.md`, L3 enterprise) and
  announce it. (`shared/maturity-detection.md`)
- Default chain on the same artifact: Visual Quality Inspector (squint, 3-second, grayscale,
  alignment, spacing, rhythm, balance, anti-patterns, font availability) → UX Critic (H1-H10,
  cognitive load intrinsic/extraneous/germane, IA) → A11y Auditor (WCAG 2.1 AA walk, contrast
  pairs, keyboard patterns, ARIA, motion a11y) → DS Compliance Checker (L2+ only) → Motion
  Reviewer (only if motion exists). (`design-review/SKILL.md`)
- A11y severity mapping: normal-text contrast failure P0; keyboard trap P0; missing label P1;
  missing skip link P2; cosmetic focus-ring styling P3. Motion: no reduced-motion handling P1;
  uncontrolled infinite loop P1; flashing over 3/s P0; duration over the token by more than 50%
  P2; layout-triggering animation P1.
- Aggregated report: "What's working (required — ≥3)"; P0-P3 tables each present (write "None"
  rather than omit); Effort S/M/L; one root cause across dimensions listed once as `[cross-dim]`;
  repeated defects rolled up as one systemic fix with the instance count; before/after mode
  reports Improvements / Regressions / Net verdict. Severity rubric in
  `shared/knowledge/ux-heuristics.md`; visual inspection checklist in `visual-quality.md`.

### 2.5 design-skills design-critique, interaction-design, ux-writing (DSK)

- Critique in nine steps: context (who, what, where, constraints); 5-second scan; heuristic
  pass; UX-law check; interaction review (posture, excise, orchestration); pattern review; IA
  review; content review; synthesise and prioritise. Feedback formula: what is wrong + principle
  + why it matters + specific recommendation. Calibrate to fidelity; a live product gets
  "Everything — full heuristic evaluation". (`design-critique/SKILL.md`)
- Heuristic evaluation: "3-5 evaluators", independent, at least two passes, severity 0-4,
  median when evaluators disagree. (`design-critique/references/heuristics-and-laws.md`,
  `templates/heuristic-evaluation-template.md`)
- State inventory per element and per page, with a transitions table and a coverage summary;
  any "Not designed" cell is a potential bug. (`interaction-design/templates/state-inventory-template.md`)
  Microinteraction quality checklist of 13 items. (`interaction-design/references/microinteractions.md`)
- Copy editing in four phases (purposeful, concise, conversational, clear) and scoring 0-10 on
  each standard; readability via Hemingway, Readable.com or Flesch-Kincaid; screen-reader,
  contrast and keyboard checks of the text. (`ux-writing/SKILL.md`,
  `references/content-usability-checklist.md`, `references/accessibility-guidelines.md`)

### 2.6 zizi-skills design-guide, frontend, plain-language (ZZ)

- Hard gates before showing UI: light and dark mode both; built output when class names are
  composed at runtime; inline screenshots; lint + build green; parallel vitest as CI runs it;
  "'The page renders' is not evidence a FORM is usable" (exercise input, validation, submit);
  "A CSS fix that 'looks right' is unverified — A/B it against the DOM" (computed styles, toggle
  the rule). (`frontend/SKILL.md` Step 4)
- Render candidates instead of reasoning about them: `scripts/montage.sh` places options beside
  the existing elements on a light row and a dark row; inspect the PNG before showing it.
  Checklist: preferences read, existing language followed, semantic colours and AA contrast,
  rendered comparison, both themes with screenshots, one recommendation. (`design-guide/SKILL.md`)
- Performance: `scripts/lh-audit.sh` with `--runs 3`, mobile and desktop compared like-for-like,

  public paths changed. (`frontend/web-performance.md`)
- Copy: pick the mode (point edit, keep the author's voice, rewrite from the record), run seven
  sweeps in order and re-run earlier sweeps on changed lines, leave-it-alone test, AI-tells
  search, collect `[NEED: …]` markers. (`plain-language/copy-sweep.md`)
